Тема: Мережі в Docker (Networking in Docker)



1. Типи мереж у Docker (драйвери)

- bridge (міст) — використовується за замовчуванням для автономних контейнерів. Контейнери в одній користувацькій bridge-мережі бачать один одного за внутрішніми IP-адресами та за іменами контейнерів (через вбудований DNS Docker). Для доступу ззовні потрібно здійснювати прокидання портів (-p).

- host — контейнер ділить мережевий простір безпосередньо з хост-машиною без ізоляції та NAT. Прапор -p ігнорується, оскільки сервіс одразу слухає порт хоста.

- none — повна ізоляція від зовнішньої мережі та інших контейнерів (доступний лише loopback-інтерфейс lo / 127.0.0.1).

- overlay — розподілена мережа для зв'язку контейнерів, запущених на різних хостах у кластері (Docker Swarm).



2. Різниця між стандартною мережею bridge та власною мережею

- У стандартній мережі bridge контейнери взаємодіють переважно за IP-адресами.

- У користувацькій мережі (наприклад, myapp-net) працює автоматичне розв'язання імен (Service Discovery / DNS): вебсервер або бекенд може звертатися до бази даних просто за ім'ям контейнера (db).



3. Як працює NAT і прокидання портів (-p)

- Запис -p 8080:80 означає перенаправлення трафіку з порту 8080 хоста на порт 80 всередині контейнера.

- Docker автоматично додає правила трансляції адрес (DNAT та MASQUERADE) у таблицю nat утиліти iptables.

- Якщо контейнер запущено без прапора -p (як flaskinternal), він ізольований від зовнішньої мережі й доступний тільки іншим контейнерам у спільній Docker-мережі.



4. Корисні команди для діагностики мережі

- docker network ls — вивести перелік усіх мереж.

- docker network inspect <мережа> — переглянути підмережу, шлюз та список підключених контейнерів.

- docker network connect <мережа> <контейнер> — підключити вже запущений контейнер до мережі.

- docker network disconnect <мережа> <контейнер> — відключити контейнер від мережі.

- sudo iptables -t nat -L -n — перевірити правила NAT на хості Linux.
